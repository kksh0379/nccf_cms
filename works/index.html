화면과 인터랙션까지 직접 구현합니다.

서비스 기획자로서 정책·화면·플로우를 설계하고, 바이브 코딩으로 실제 동작하는 프로토타입까지 만들어 검증합니다. 아래는 직접 기획하고 구현한 작업물과, 각 작업의 기획 의도·구현·강점을 정리한 기록입니다.

김상화 · 서비스 기획 / 프로젝트 관리 — 정책·UX·관리자(CMS)·데이터 흐름 설계

STRENGTH 01

정책 → 화면 → 인터랙션의 일관성

운영 정책을 화면과 동작으로 끝까지 연결합니다. 예외·비활성 상태·안내 문구까지 설계해 사용자가 오류로 오인하지 않게 합니다.

STRENGTH 02

직접 만드는 프로토타입

말과 문서로 설명하기 어려운 흐름을 실제 동작하는 화면으로 만들어, 현업·개발과의 의사결정을 빠르게 합니다.

STRENGTH 03

운영 환경과 동일한 재현

신청 → 확인 팝업 → 완료, 관리자 CMS 흐름 등 실제 운영과 같은 구조로 구현해 설명·검수에 바로 쓸 수 있습니다.

01

프로젝토리 — 활동/이벤트 예약 & 운영

두 지역(서울·성남)을 운영하는 활동 예약 서비스의 사용자·관리자 화면. 정책을 UX로 옮기는 데 초점을 맞췄습니다.

사용자 · PC/모바일

활동 예약 — 지역 간 중복예약 제한

PC / 모바일 · 정책 기반 예약 UX

개요지역·날짜·시간을 선택해 활동을 예약하는 화면. 같은 날짜에 서울(혜화)·성남을 중복 예약할 수 없는 정책을 담았습니다.
기획타 지역 예약이 있으면 버튼마다 검증하지 않고 선택 날짜+지역 기준으로 예약 영역 전체를 비활성하도록 설계. 오류 오인을 막기 위해 제한 사유 안내 + 마이페이지 바로가기를 함께 제공.
구현단일 게이트 함수로 상태 판단, 신청 → 활동예약 확인 팝업 → 완료(운영 동일 구조), 화면 간 상태는 localStorage로 공유, 취소 시 새로고침 없이 즉시 해제.
강점정책 기반 UX · 단일 상태원으로 유지보수 용이 · 운영 플로우 재현.
